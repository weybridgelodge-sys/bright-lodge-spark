- Lodge addresses, site URL and sender names come from lodgeSettings.ts (lodge_contact_settings + Unit Setup); typed fallbacks are neutral only ("" / "Your Lodge" / example.com), never host-lodge values; sender domains live in emailDomains.ts; links in emails use configuredSiteUrl (no fallback; blank = no link). Why: clone-safe, one editable source.
- Public event bookings use the separate events Stripe (_shared/stripe-events.ts, STRIPE_EVENTS_*) and event_* tables, never lodge Stripe. Why: events money stays off the lodge ledger.
- Event money: one event_booking_payments row per Stripe charge; totals via recomputeBooking; balance tokens service-role only. Why: per-payment refunds, private links.
- Newsletter sign-up is double opt-in (_shared/newsletterOptIn.ts); store token hash only; sends/counts need confirmed=true. Why: no subscribing others.
- Booking greetings via _shared/greeting.ts; saves trim names. Why: titles greeted as names.
- Unpaid lodge card bookings: 60-min Stripe hold; hourly expire-pending-bookings asks Stripe first (paid → shared markBookingPaid, expired+15-min grace → delete); register rows only for non-pending/failed bookings (trigger WHEN + _shared/pendingBookingExpiry.ts). Why: never lose a payment, no ghost register rows.
- Return emails (Provincial, UGLE) Cc the current Secretary/WM and file the sent PDF to Documents 'returns' via returnFiling.ts; who sees Returns = public.can_view_return_documents(). Why: one rule, one place to change.
- Booking contact: _shared/bookingContact.ts (Unit Setup booking_contact_email → "contact us"; else Assistant Secretary only while current_officer_holder has one; else Secretary; else no address), mirrored in get_public_booking_details (contact_email + contact_office); used by duplicateBookingMessage, CheckoutReturn, booking email reply-to/notify. Never type an address. Why: no futile mail to a vacant office.
- Edge-function PDFs (pdf-lib) use _shared/pdfLibBrand.ts (Deno twin of src/lib/pdfBrand: loadCrest 12s timeout, imagescript downscale/flatten, failure = omitted); newsletter archive built in _shared/newsletterArchivePdf.ts. Sign-in emails use EmailBrandHeader/Footer via email-templates/_layout.tsx setAuthEmailBrand; auth-email-hook renders with cached Unit Setup or waits ≤1500ms for one shared lookup (_shared/authEmailBrand.ts), else text-only header from SITE_NAME. Newsletter broadcasts send every audience before building archive PDFs (_shared/newsletterDispatch.ts; crest once per send, 10s per image). Why: brand parity without risking or delaying sends or sign-ins.
- Email sending domains live only in _shared/emailDomains.ts (deployment-level, tied to verified DNS, never Unit Setup); sign-in default links use Unit Setup site_url via authEmailBrand siteUrlFor. Why: unverified domains cannot send.
